# Security controls

## Authentication and authorisation

- Passwords are hashed with scrypt (`n=2^14`, `r=8`, `p=1`, 64-byte output, random 16-byte salt).
- Administrator sessions use a random 256-bit token; only an HMAC-SHA256 hash of the token is stored.
- Cookies are `HttpOnly`, `SameSite=Lax`, `Secure` in HTTPS deployments, and scoped to `/`.
- Absolute session lifetime (12 h) and idle expiry (2 h) are enforced server-side.
- Every admin page and mutation requires an authenticated, authorised session.
- First-time/generated passwords set `must_change_password`; the user cannot access other admin pages until it is changed.
- Failed sign-ins are throttled by IP and username in `login_attempts`.

## CSRF and injection

- All state-changing admin forms require a per-session CSRF token; the login form uses a pre-auth visitor token.
- Tokens are compared with `hmac.compare_digest`.
- All SQL uses parameterised queries.
- Jinja2 auto-escaping is enabled; release notes are rendered as plain text lines, never as raw HTML.
- Canonical/redirect targets are validated so `next=` cannot cause an open redirect.

## File and download safety

- Installers and screenshots are stored outside the database under `storage/`.
- Uploaded paths are generated by the server; user file names are never used for storage paths.
- Only `.exe` and `.msi` installers with valid PE/MSI signatures are accepted.
- Screenshots must have genuine PNG/JPEG/WebP magic bytes.
- Download paths are resolved and confirmed to stay inside the release storage root (path traversal returns a controlled error).
- Downloads are served with `application/octet-stream`, `Content-Disposition: attachment`, `nosniff` and the published checksum in `X-Checksum-Sha256`.
- The payload filter rejects development files, debug symbols, temporary data, user settings, encrypted keys, conversation history and user-trained model checkpoints.

## Response hardening

Every response sets:

- `Content-Security-Policy` (self-only scripts, styles, images, connections; no framing)
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy` denying microphone/camera/geolocation/payment
- `Cache-Control: no-store, private` for admin pages

## Verification before publication

`tools/verify_release.py` and the admin **Verify** action check:

1. Installer exists and is readable.
2. Size and SHA-256 match stored metadata.
3. PE/MSI signature matches the extension.
4. All required embedded application/runtime/model/licence files are present and hashed.
5. No development, temporary or private user files are embedded.
6. A passing application smoke test is recorded.

## Tests

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Security tests include CSRF rejection, unauthenticated admin access, cookie flags, security headers, login throttling, path traversal, XSS escaping, unpublished release protection and packaging exclusions.

## Reporting a vulnerability

Do not open a public issue. Contact the SHADOW project owner privately with reproduction steps, affected version and impact. Include the release SHA-256 when reporting a download problem.
